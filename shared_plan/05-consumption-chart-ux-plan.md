# 消費支出（名目／実質）チャート UI 改善プラン（配色を除く）

## 0. スコープ

対象は `#section-consumption-nominal` / `#section-consumption-real` の2チャート
（`SpendingBarChart.tsx` と、それを描画する `CpiChart.tsx:593-655`）。

**配色（費目ごとの色の割り当て・パレット値）は本プランの対象外**とする。
色に関する事項は `04-stacked-chart-palette-plan.md` および
`cpi-palette-lch-table.md` が扱う。本プランが色に触れるのは
「不透明度」「セグメント間の隙間」といったマーク仕様の範囲に限る。

## 1. 調査方法

`pnpm run build` 済みの `next start` に対し Playwright で実機描画を取得し、
desktop(1280×900) / mobile(390×844) の両方で名目・実質チャートおよび
ツールチップ表示状態をスクリーンショットして確認した。コード側は
`SpendingBarChart.tsx` / `CustomTooltip.tsx` / `resetLogic.ts` /
`chartConstants.ts` を読み合わせている。

なお「セクション見出しが sticky タブバーに隠れる」ように見えるのは
`element.screenshot()` が sticky 要素の重なりごと切り出すための**撮影上の
アーティファクト**で、実測では h2 の top=80px に対しタブバーの bottom=61px と
干渉しない（`scrollMarginTop: 5rem` が正しく効いている）。実バグではない。

## 3. 発見した課題

### P0-1. 実質チャートに凡例が一切ない（最重要）

- **箇所**: `CpiChart.tsx:651` の `hideLegend`、`SpendingBarChart.tsx:76-87`
- **現状**: 実質チャートには凡例の代わりに「凡例は『消費支出（名目）』と連動しています。」
  という1行の注記とアンカーリンクだけがある。
- **なぜ問題か**:
  1. **系列の同定手段が色だけになる**。10費目＋参考系列が積み上がった棒から、
     凡例なしに「この紫は食料」と読む方法がない。「2系列以上のチャートには常に
     凡例を置き、識別を色のみに依存させない」という原則に正面から反する。
  2. **モバイルでは名目チャートまで1画面以上離れている**。アンカーリンクを踏むと
     ページの別の場所へ飛ばされ、実質チャートでの閲覧位置を失う。戻る手段もない。
  3. 四半期(Q1〜Q4)トグルも実質側には存在しないため、実質チャートだけを見ている
     ユーザーには絞り込み機能があること自体が伝わらない。
- **`01-uiux-improvement-plan.md` の P2-4 と同一の問題**。同プランでは「読み取り専用
  凡例」を案としているが、**押せそうに見えて押せない UI はかえって操作を阻害する**ため、
  本プランでは後述のとおり操作可能な凡例をそのまま出す方針を採る。

### P0-2. ツールチップのラベルが凡例と食い違う

- **箇所**: `CustomTooltip.tsx:187` が `entry.name`（＝生の dataKey）をそのまま描画
- **実際の表示**:

  | ツールチップ               | 凡例・データテーブル |
  | -------------------------- | -------------------- |
  | `その他の消費支出（名目）` | `諸雑費・CPI外支出`  |
  | `住居（名目）`             | `住居`               |
  | `被服及び履物（名目）`     | `被服及び履物`       |

- **なぜ問題か**: `諸雑費・CPI外支出` と `その他の消費支出` は**文字列として全く
  別物**であり、同一系列だと気づけない。凡例で費目を非表示にしてもツールチップ側の
  該当項目が消えるだけで、名前が対応しないため因果が読めない。
- `getLegendLabel`（`DISPLAY_LABEL_OVERRIDES` 込み）が凡例（`SpendingBarChart.tsx:128`）と
  データテーブル（`CpiChart.tsx:464`）には適用されているのに、ツールチップだけ
  適用漏れになっている**実装の不整合**であり、意図的な仕様ではない。

### P1-1. ツールチップに合計がなく、ゼロ系列が並び、順序が積み上げと逆

積み上げ棒グラフのツールチップとして3点の欠落がある。

- **合計がない**: 積み上げグラフで最も知りたい「その四半期の消費支出合計」を、
  ユーザーが10個の数字を暗算しないと得られない。
- **値0の系列が表示される**: 2017Q1以降は `民間最終消費支出（名目）：0.00` が
  毎回並ぶ（データソースの切替により当該期間は値を持たないため）。ノイズであり、
  かつ「消費支出がゼロ」という誤読を招く。
- **並び順が視覚と逆**: `payload` の順＝積み上げの下から上。一方チャートを見ている
  ユーザーは上から下に読む。デスクトップ（`CustomTooltip.tsx:70`）は payload 順を
  そのまま使うため、ツールチップ先頭の `住居` はチャートでは最下段にある。
- （モバイルは `:64-73` で値の降順 top5＋「他 N 件」に切り替わる。上位を見せる
  意図は妥当だが、並び替えによりチャートの積み上げ位置との対応がさらに失われる。）

### P1-2. 2017Q1 のデータソース切替がチャート上で無説明

- **現状**: 2005Q1〜2016Q4 は灰色の `民間最終消費支出`（四半期別GDP統計）のみ、
  2017Q1以降は10費目の内訳（分布調整済み原数値CTI）のみが描画される。
  グラフ上では**灰色の棒が突然途切れて色付きの積み上げに変わる**ようにしか見えない。
- **なぜ問題か**: 「2017年に何かが起きた」というデータ上の断絶に見えるが、実体は
  出典の切替である。説明は ⓘ ポップオーバー（`chartInfoContent.ts:73-98`）の中に
  しかなく、チャートを見ただけでは到達しない。時系列比較を主目的とするチャートで、
  最も誤読を招く箇所が無注記になっている。
- **既存資産**: `YearReferenceLines`（`SpendingBarChart.tsx:143`）で参照線を引く
  仕組みが既にあり、同じ仕組みを流用できる。

### P1-3. モバイルで凡例がチャートより広い面積を占める

- **実測（390×844）**: 「四半期」見出し＋Q1〜Q4行＋費目チップ6行で凡例ブロックが
  約300px。セクション全体の3割強を占め、チャート本体が押し下げられる。
- P0-1 を素直に実装すると実質チャートにも同じ300pxが増え、**モバイルの縦スクロール量が
  さらに悪化する**。P0-1 と P1-3 はセットで解く必要がある。
- 注意: 横スクロール1行にまとめる案は採らない。`03-section-tabs-scrollbar-plan.md`
  で扱ったとおり、`overflow-x: auto` は環境によってスクロールバーが常時可視になる
  問題を招く。

### P2-1. 「全選択解除」ボタンのラベルが状態を反映しない

- **箇所**: `SpendingBarChart.tsx:108`、ロジックは `resetLogic.ts:26-27`
- **現状**: 実装は「非表示が1つでもあれば全表示、そうでなければ全非表示」の
  **トグル**。しかしラベルは常に「全選択解除」で固定。全非表示の状態でも
  「全選択解除」と書かれており、押すと全選択される。
- `aria-pressed` も付いていない（他の凡例ボタンには付いている）。

### P2-2. 参考系列が費目と同じ `stackId` に積まれている

- **箇所**: `SpendingBarChart.tsx:175` — 全系列が `stackId="a"` を共有
- **現状**: 合計にあたる `民間最終消費支出` が、その内訳であるはずの10費目と
  同じスタックに積まれている。意味的には二重計上だが、2016年以前と2017年以降で
  **値を持つ期間が重ならないため今は破綻していないだけ**。
- **リスク**: 将来 CTI 期間側にも参考系列を併記した瞬間、無言で二重計上のグラフに
  なる。現時点でバグではないため優先度は下げるが、放置すべきではない。

### P2-3. Y軸に単位（指数の基準）の表示がない

- 値は「2020年平均＝100」の指数だが、軸にもチャート周辺にも書かれていない
  （ⓘ ポップオーバー内のみ）。120 や 90 という数値が何を意味するか、チャート
  単体では判断できない。

### P2-4. 単一費目だけを見る手段がない（solo）

- 11系列中1つだけを見たい場合、10回タップが必要。`01-uiux-improvement-plan.md`
  の P3-4 と同じ指摘だが、消費支出セクションは名目・実質の2チャートが同じ状態を
  共有するため、solo があれば両方に同時に効き、効果が大きい。

## 4. 実装方針

### Phase 1 — 情報の正しさ（P0）

#### F-1. ツールチップに表示ラベル整形を通す

`CustomTooltip` に任意の `nameFormatter?: (name: string) => string` を追加し、
未指定時は恒等関数とする（他チャートへの影響ゼロ）。`useChartTooltipProps` に
formatter を受け渡す引数を足し、消費支出チャートからは `getLegendLabel` を渡す。

接尾辞「（名目）」「（実質）」はチャートタイトルで自明なため、`getLegendLabel` に
よる除去をそのまま活かす。

#### F-2. 実質チャートに凡例を出す

`hideLegend` を廃し、実質チャートにも四半期トグル・費目凡例を表示する。
状態（`nominalHiddenKeys` / `realHiddenKeys` / `hiddenQuarters`）は現行どおり
`handleLegendToggle` と `createDualResetHandler` で両チャート連動のまま維持する
（連動自体はユーザーが名目と実質を同条件で比較するための仕様なので変えない）。

「名目と連動している」旨の注記は凡例の直下に**残す**。ただしアンカーリンクは
不要になるため削除する（飛ばす必要がなくなる）。

#### F-3. ツールチップの内容を積み上げ棒向けに整える

- 値が 0 / null の項目を除外する
- 合計行を追加する（`showTotal` prop。既定 false で他チャートに影響させない）
- デスクトップの並びを積み上げの視覚順（上→下）に合わせて反転する
- モバイルの top5 表示は維持しつつ、合計行は常に表示する

### Phase 2 — 誤読の防止（P1）

#### F-4. 2017Q1 に出典切替の参照線と注記を入れる

`YearReferenceLines` と同様の仕組みで 2017Q1 に破線＋ラベルを描画し、
チャート直下の注記に「2016Q4まで＝四半期別GDP統計／2017Q1以降＝CTI」を明示する。
凡例の `民間最終消費支出` にも期間の補足を添える。

#### F-5. モバイルで凡例を折りたたむ

モバイル幅では凡例ブロックを既定で折りたたみ、「凡例・絞り込み」を開くボタンを
置く。デスクトップは現行どおり展開したままとする。F-2 で増える縦方向の負担を
ここで相殺する。

### Phase 3 — 仕上げ（P2）

- F-6: リセットボタンのラベルを状態連動（「全て表示」⇄「全て非表示」）にし、
  `aria-pressed` を付与
- F-7: 参考系列を別 `stackId` に分離（見た目は現状維持）
- F-8: Y軸の単位表記を追加（軸ラベルまたはチャート直下の注記）
- F-9: 各費目に solo ボタンを追加（`01` の P3-4 と統合して実施）

## 5. 検証方針

`bugfix-tdd` スキルの手順に沿い、**先に落ちるテストを書いてから実装する**。
E2E は必ず `pnpm run build` 済みの成果物に対して実行する（`.next` の陳腐化により
変更が反映されないまま検証する事故を避ける）。

| 項目 | 検証                                                                                                                         |
| ---- | ---------------------------------------------------------------------------------------------------------------------------- |
| F-1  | ツールチップに `諸雑費・CPI外支出` が出て `その他の消費支出（名目）` が出ないこと（E2E）                                     |
| F-2  | `#section-consumption-real` 内に費目凡例ボタンとQ1〜Q4が存在すること（E2E）                                                  |
| F-2  | 実質側の凡例クリックで**両チャートの棒本数が変わる**こと（既存 `spending-filter.e2e.spec.ts` と同じく実データ変化を assert） |
| F-3  | 値0の系列がツールチップに現れないこと／合計行の値が各項目の和と一致すること                                                  |
| F-4  | 2017Q1 の参照線要素が存在すること                                                                                            |
| F-5  | 390px 幅で凡例が既定折りたたみ、開閉が機能すること（`mobile-pixel` プロジェクト）                                            |
| 全体 | `pnpm run test:all` → `pnpm run build` → `pnpm run test:e2e` の通過                                                          |

`AGENTS.md` の仕様書ルールに従い、コンポーネント構成・要件が変わる F-2 / F-4 は
`openspec/specs/nextjstest/spec.md` の Component Tree / Requirements にも反映する。

## 6. 非採用

- **名目・実質の凡例連動を解除して独立させる**: 2つのチャートは同一費目を
  名目/実質で対比するためのものであり、絞り込み条件が食い違うと比較にならない。
  連動は仕様として維持する。
- **凡例の横スクロール化**: `03-section-tabs-scrollbar-plan.md` と同じ理由
  （環境依存でスクロールバーが常時可視化する）で採らない。
- **名目・実質を1チャートに統合／切替タブ化**: 上下に並べて同時に見比べられる
  現在の構成のほうが目的に合う。セクションタブの構成変更も伴い影響範囲が広い。
- **配色・パレットの変更**: 本プランのスコープ外（冒頭のとおり）。
