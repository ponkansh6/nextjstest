# 消費支出（参考）を民間最終系列とCTI系列の2系列に分離する

## Context

3種比較（`new-graph`）の `消費支出（参考）` 系列で、**2014年4月の増税（5%→8%）よりも
2019年10月の増税（8%→10%）の駆け込み需要の方が大きく描かれている**。
経済的実態（税率引き上げ幅 3pt vs 2pt、2019年は食料品軽減税率あり）とは逆であり、
チャートの読み手を誤らせる。

原因を切り分けた結果、**処理方法ではなく統計ソースの継ぎ目が原因**と判明した。

一本化方針（全期間GDP統一）を検討・試算したが、**直近水準が大幅に跳ね上がる副作用（2026年3月 110.36 → 118.33、チャートの含意が反転）を許容できない**ため却下し、**データソースは変更せず、2つの独立した系列（民間最終消費支出 と CTI消費支出）として並置・分離する**方針に転換した。

---

## 原因分析（実測値）

### 継ぎ目の場所

`server/lib/data-loader/earnings.ts` の `buildConsumptionMap` が2017年で
ソースを切り替えている。

| 期間           | ソース                                            |
| -------------- | ------------------------------------------------- |
| 2016年12月以前 | 四半期別GDP統計「民間最終消費支出（名目原系列）」 |
| 2017年1月以降  | CTI（消費動向指数）「消費支出（名目）」           |

**2014Q1はGDP、2019Q3はCTIで測られている。別の物差しである。**

### 検証1: 同一イベント（2019年増税）を両ソースで測る

2019年の増税は両統計が重複してカバーしているため、直接比較できる。

| 測る物差し           | 2019Q3 YoY | 2019Q4 YoY | 駆け込み振幅 |
| -------------------- | ---------- | ---------- | ------------ |
| GDP 民間最終消費支出 | +0.99%     | −1.99%     | **2.97pt**   |
| CTI 消費支出（名目） | +3.91%     | −4.28%     | **8.19pt**   |

同じ現実の出来事が、CTIでは **2.8倍** に描かれる。

### 検証2: 物差しを揃えると順序が逆転する

GDP系で両イベントを比較すると、実態通り2014年の方が大きい。

| イベント                        | 駆け込み振幅 |
| ------------------------------- | ------------ |
| 2014年（Q1 +3.99% → Q2 +0.44%） | **3.55pt**   |
| 2019年（Q3 +0.99% → Q4 −1.99%） | **2.97pt**   |

帰属家賃を除いたベースでも 4.06pt vs 3.81pt で2014年が上。

### 検証3: 処理方法は無罪

「四半期値を3か月に展開 → 12か月移動平均」が2014年を潰している疑いを直接検証した。
2019年のCTI月次を四半期フラット化して同じ12MAに通すと:

```
2019年9月ピーク→12月の下げ幅:  月次のまま 1.15pt / 四半期フラット化 1.15pt
→ 時間解像度による減衰: 0%
```

12MAの窓が四半期の整数倍なので、解像度低下は完全に打ち消される。**処理方法の寄与はゼロ。**

### 検証4: 「CTIが一般的にノイジー」でもない

重複期間2018-2025のYoY標準偏差は GDP系 3.39pt / CTI系 3.56pt（増幅率1.05倍）、
コロナ期を除くと0.92倍。コロナショック自体も両者ほぼ一致。

**消費税駆け込みという事象に限って**両ソースが食い違う。
家計調査ベースのCTIは耐久財の買いだめ・駆け込みを鋭く拾うのに対し、
SNAはコモディティフロー法で供給側から推計するため均される、という性質差である。

### 現行チャート上の見え方

`消費支出（参考）`（12MA, 2020=100）実測値:

| 期間   | 挙動                                                                |
| ------ | ------------------------------------------------------------------- |
| 2014年 | 2014年3月 99.69 → 12月 100.01。山が存在せず傾きの変化にしか見えない |
| 2019年 | 2019年9月 104.49 が明確なピーク → 12月 103.35 へ **−1.14pt** の急落 |

## 採用方針：2系列への分離

現行の「消費支出（参考）」1系列（2017年でソース切替）をやめ、**2つの独立した系列として用意する**:

1. **民間最終消費支出（参考）**: 2005〜2017年、GDPベース（四半期別GDP統計「民間最終消費支出（名目原系列）」）
2. **CTI消費支出（参考）**: 2018年〜、CTIベース（分布調整済み原数値CTI「消費支出（名目）」）

- 各系列は自身の期間のみ値を持ち、期間外は `null` / 欠測（重複なし、継ぎ目での接続・補間はしない）
- 3種比較（NewGraph）に2本のラインとして並置し、物差しが異なることを視覚的に明示する
- **動機**: 一本化方針の副作用（直近水準の跳ね上がり・含意反転）を回避しつつ、統計の継ぎ目を隠さず正直に並べるため。

### スコープ境界（重要）

本変更は **`new-graph`（3種比較）における消費支出系列のみ**が対象。

以下は **対象外**:

- 四半期積み上げチャート（`computeQuarterlyAggregates` / `server/lib/view-models/quarterlyAggregation.ts`）
- `SpendingBarChart` / `StackedAreaChart` の9大費目内訳
- `applySupportSeriesScaling`（`server/lib/math/supportSeries.ts`）
- 従来の単一「消費支出（参考）」を表示する他の個別ブロック（必要に応じ維持または非表示）

## 変更による副作用

### 副作用1: 2系列化に伴う比較の制限

2系列に分かれるため、2014年と2019年の駆け込みを単一の連続ライン上で直接比較できなくなる（物差しが異なるため、そもそも直接比較すべきでない）。

### 副作用2: 直近水準の跳ね上がりは発生しない

一本化案で懸念された「直近水準が 118.33 へ跳ねる」問題は発生しない。各系列は現行ソースのままなので、水準・含意は現行のまま維持される。

### 副作用3: 新たな誤読リスクへの対策

グラフが3本から4本に増える（給与・物価 + 消費2系列）。凡例・説明文で2系列の意味（期間と統計の違い、物差しが異なるため直接比較不可であること）を明確に注記する必要がある。

## 実装手順

### 1. `server/lib/data-loader/earnings.ts` — 2系列への分離

`buildConsumptionMap`（`:50-74` 付近）を改修し、`民間最終消費支出（名目）`（2005-2016のみ）と `消費支出（名目）`（2017-のみ）を別々のMapまたはプロパティで保持するように変更する。

### 2. ビューモデルと型の更新

- `src/types/data.ts` の `EarningsView` 型に2つの系列キー（例: `民間最終消費支出（参考）` と `CTI消費支出（参考）`）を追加。
- `src/app/page.tsx` の `toEarningsView` で2系列をビューモデルにマッピングする。

### 3. `NewGraph.tsx` の改修

- `LINE_CONFIGS` に2系列を追加（色を分ける。例: 民間最終消費支出=赤系、CTI消費支出=橙系 など既存パレットに合わせて）。
- `connectNulls={false}` を維持し、期間外は `null` で途切れさせる。

### 4. `src/lib/chartInfoContent.ts` — 説明文の更新

`new-graph` ブロックの説明文を2系列の説明に差し替え（各系列の期間・統計・「物差しが異なるため直接比較不可」の注記）。

### 5. テストの更新と新規追加

- `tests/data-quality/earning-data-integrity.test.ts` の継ぎ目連続性テストを、**「2系列の期間が重複せず、それぞれの期間のみ値を持つ」ことを検証するテスト**に置き換え。
- 新規回帰テスト: 「2014年（民間最終系列）と2019年（CTI系列）が別系列として存在し、値がそれぞれの期間のみに存在する」ことを検証。
- `tests/unit/chart-info-content.test.ts`: 新しい説明文に合わせて更新。

### 6. 仕様書更新 `openspec/specs/nextjstest/spec.md`

データモデル、Data Flow、R3b 等を2系列化に合わせて更新。

### 7. 検証

- `pnpm type-check` / `pnpm lint` / `pnpm test` / `pnpm test:e2e` / `pnpm build`
- `pnpm dev` で3種比較タブを目視確認（2系列が正しく描画されること、継ぎ目で線が途切れること）。

## 却下した代替案

| 案                                      | 却下理由                                                                                      |
| --------------------------------------- | --------------------------------------------------------------------------------------------- |
| 一本化（全期間GDP統一）                 | 直近水準が 118.33 へ跳ね、チャートの含意が反転する（副作用2）。世帯数正規化もデータ不在で不可 |
| 継ぎ目の明示（線・注記のみ）            | ソース切替を隠したまま1系列として描画するため、物差しの違いを視覚化できず誤読リスクが残る     |
| 2016年以前の振幅をCTI相当に補正（×2.8） | 増幅率の根拠が重複イベント n=1 のみ。恣意的な加工                                             |
| 月次SNA消費データの導入                 | 日本の四半期GDP統計に月次系列が存在しない                                                     |
| 世帯数で除して正規化                    | 世帯数データ未取得。人口代用は悪化                                                            |
