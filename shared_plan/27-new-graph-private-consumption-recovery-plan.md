# 3種比較「民間最終」の表示復旧プラン

作成日: 2026-09-13
状態: 実装・検証完了
対象: 3種比較（NewGraph）の民間最終消費支出。ユーザー指示に従いサブエージェントは使用していない。保存先は既存の `shared_plan/` に合わせた。

## 調査結果

この節の初期観測は履歴であり、最終判定は後段のFinal Verificationによる。

### 確認できた主因

`server/lib/data-loader/cpi.ts:1077` 以降では、通常の2025年基準経路で年次GDPを `mapped` の各月に付与する。その後、同ファイルの `existingMonths` 以下で1994〜2016年の不足月を追加する。通常経路の追加行には年月しか入らず、先に終わったGDP付与処理の対象にならない。

`server/lib/data-loader/earnings.ts:97` の `buildConsumptionMaps` は、その欠けた月次入力から民間最終の移動平均を作る。`hasGdpComparison` は2017年以降の値でtrueになるが、2005〜2016年は値がなく、同ファイルの参考系列出力はnullになる。`src/app/page.tsx` → earnings projection → `CpiChart` → `NewGraph` へ渡す前に欠測が生じている。

`NewGraph.tsx` は全欠測の線を除外しつつ凡例を残すため、2016年以前に絞ると「民間最終」の凡例だけが残る。これはコードからの帰結であり、実ブラウザーでの描画確認は今回未実施。

### 通常ローダーの実測

`node --import tsx` で `loadCtiData()` と `loadTotalEarningData()` を引数なしで直接実行した。

| 項目                               | 結果                                        |
| ---------------------------------- | ------------------------------------------- |
| 通常の参考系列の有限値             | 12件、2017年1月〜12月のみ                   |
| 延長系列の有限値                   | 96件、2018年1月〜2025年12月                 |
| 2005年1月 / 2014年6月 / 2016年12月 | 通常・延長ともnull、CTI行のGDP原値も未設定  |
| 2017年1月 / 12月                   | 通常系列86.37522309807025、年次原値303099.9 |
| 2018年1月                          | 延長系列86.44084045694056                   |
| 2025年12月                         | 延長系列100                                 |

最初の `pnpm exec tsx` はサンドボックスのIPCソケット制約（EPERM）で失敗したため、IPC不要の `node --import tsx` で実測した。アプリの不具合ではない。調査開始時の作業ツリーはクリーン。

### 見逃しを生んだテスト

- `tests/data-quality/earning-data-integrity.test.ts` は `loadEarning2020RollbackFixture()` を使う。156か月の通常系列を検証していても、通常の2025年基準経路の欠測を検出できない。
- `tests/data-quality/cti-gdp-source-integrity.test.ts:150` の過去行チェックは、2016年のaliasと比較指数の等値だけを確認する。両方undefinedでも成功する。行の存在だけではGDP値の存在を保証できない。

### 関連して確認した仕様不整合

- 現在の通常3種比較は「年次名目GDPを同年の月へ複写→12MA」である。`chartInfoContent.ts` の3種比較説明は「名目・実質各1系列を四半期粒度」「四半期の独立照合pendingなら非表示」となっており、実際の経路と一致しない。
- `computeTrailingMA12` は有限値だけを抽出し、先頭12か月未満でも平均を返す。途中欠測も詰めて計算するため、「連続する12か月がそろう場合だけ計算」という説明を満たしていない。
- 2018年以降の通常系列がnullで、延長系列がadvanced時だけ表示されるのは既存の期間分割仕様。今回確認した過去の欠測とは区別する。

## 推奨方針

まず現在の年次GDP・2025年正規化の契約を維持して過去期間を復旧する。四半期ソースへの切替は値の形状と尺度の検証が必要な別変更とする。年次値から月次の実測変動を復元したと説明しない。旧2020年fixtureの数値へ戻すことを復旧条件にしない。
