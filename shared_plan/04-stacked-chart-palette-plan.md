# 費目別寄与度チャート 配色・ビジュアル改修プラン

作成日: 2026-08-11
対象: `物価指数 費目別寄与度`（`StackedAreaChart`）の配色・チャートクローム
主要ファイル: `src/lib/chartConstants.ts` / `src/app/globals.css` / `src/app/components/StackedAreaChart.tsx` / `src/app/components/CpiChart.module.css` / `src/hooks/useChartTheme.ts`
方針: **チャート系列色をテーマ機構の内側に入れ、light / dark それぞれで「選ばれた配色」にする。** 現状のナイトモードは light 用パレットの流用であり、これが全ての不具合の根本原因である。

---

## 0. 背景 — 現状分析の結論

系列12色は `chartConstants.ts:79` の `stackedColors` にハードコードされた単一定義で、light / dark 両方に同じ値が使われている。軸・グリッド・ツールチップは CSS 変数でテーマ追従しているため、**チャート色だけがテーマ機構の外にある**。

塗りは `fillOpacity={0.8}`（`StackedAreaChart.tsx:123`）で下地に合成されるため、実際に画面に出る色は定義値と異なる。以下は合成後の実測値。

| 検査項目                           | light（`#ffffff` 下地）         | dark（`#1a1a1a` 下地） |
| ---------------------------------- | ------------------------------- | ---------------------- |
| 明度バンド                         | FAIL                            | FAIL                   |
| 彩度フロア                         | FAIL（諸雑費 C 0.091 = グレー） | FAIL（諸雑費 C 0.095） |
| CVD 分離（目標 ≥8）                | **3.1** FAIL                    | **3.2** FAIL           |
| 通常視力フロア（ハードゲート ≥15） | **3.9** FAIL                    | **3.4** FAIL           |
| 背景コントラスト（≥3:1）           | 7件が未達                       | 5件が未達              |

### 致命的な所見

1. **外食以外食料 `#c21a00` / 外食 `#b01500` / 諸雑費 `#550500` が同一色相に縮退。** 上位3帯が「赤の明度違い」になっており、通常視力でも ΔE 3.9 で判別困難。積み上げでも凡例でも隣接するため、識別手段が存在しない。
2. **dark で積み上げの両端が背景に同化。** 住居 1.24:1 / 諸雑費 1.10:1。積み上げの総高が読めない。
3. **凡例スウォッチが dark で見えない。** 塗り（α 0.8）と違いスウォッチは生色（`StackedAreaChart.tsx:69`）。住居 1.34:1 / 諸雑費 1.17:1。
4. **light では逆に中間の明るい系列が沈む。** 光熱・水道 1.23:1 / 通信 1.48:1。**モードごとに落ちる系列が逆**であり、単一パレットで両モードを賄えないことの直接的な証拠。
5. **帯の分離線がモード間で逆転。** `stroke={gridStroke} strokeWidth=1 strokeOpacity=0.4`（`StackedAreaChart.tsx:119-121`、01プランの P4-5 実装）は light では白に近く不可視、dark では暗線として働く。

### 現状で維持されている点（改修時に壊さないこと）

- 色が系列に固定されており、フィルタしても残存系列が塗り替わらない（`stackedKeys` インデックス参照）。
- 凡例が常時表示され、`aria-pressed` と `line-through` により凡例側は色のみに依存していない。
- データテーブルへの導線があり、コントラスト救済要件の一部を満たしている。
- 単一 Y 軸、`:focus-visible` アウトラインあり。

## 2. 新パレット（確定値）

12スロットを **明暗2ティア交互配置** で構成する。低明度で彩度を保てない色相域（シアン〜黄緑、OKLCH で L 0.46 のとき最大彩度 0.078〜0.108）を明ティアに固定し、暗ティアは青〜紫〜赤域から取る。隣接スロットが必ずティアをまたぐため、色相差に加えて明度差が分離を担保する。

- 明ティア: light `L 0.745` / dark `L 0.665`
- 暗ティア: light `L 0.46` / dark `L 0.50`
- 彩度上限 `C 0.20`（各色相のガマット上限の 95% でクリップ）

## 3. 実装項目

### Phase 0 — 基盤

#### F-1 系列色の CSS 変数化

`src/app/globals.css` に `--series-1` 〜 `--series-12` を追加する。既存の3スコープ構成をそのまま踏襲すること。

- `:root, :root[data-theme="light"]` … light 値
- `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) }` … dark 値
- `:root[data-theme="dark"]` … dark 値

`:not([data-theme="light"])` ガードにより、OS が dark でもテーマトグルの light 指定が勝つ現行の挙動を維持する。

```
light: #0c5a9a,#9fbb21,#6c2cb4,#26cd65,#90108b,#26c6af,#3f40c4,#26c2d1,#a0104b,#fc875e,#97310a,#d0a720
dark:  #0f66ac,#89a01b,#773ac1,#1fb056,#9d2398,#1faa96,#484dd2,#1fa6b3,#b31355,#f35c19,#a9380d,#b28f1a
```

#### F-2 `stackedColors` の変数参照化

`chartConstants.ts:79` を `["var(--series-1)", …]` に置換する。

- Recharts の `fill` は SVG 属性へ素通しされるため `var()` が機能する。
- 凡例スウォッチの `backgroundColor`（`StackedAreaChart.tsx:69`）でも同様に機能する。
- CSV エクスポート（`csvExport.ts`）は色を扱わないため影響なし（確認済み）。
- `CpiChart.tsx:70` および `:187` のフォールバック `"#64748b"` も変数化する。

#### F-3 検証スクリプトの常設化

`scripts/validate-palette.mjs` としてリポジトリに配置し、light / dark 両パレットを機械検証できる状態にする。パレットを変更したら自動で FAIL が出ることが目的。V-2 のテストから呼ぶ。

## 4. 残存リスクと未決事項

### R-1 全ペア検証は通らない（設計上の許容）

新案も `--pairs all`（全ペア）では FAIL する。**12系列でこれを通せる配色は存在しない**（リファレンスパレットでも全ペア保証は3スロットまで）。積み上げエリアでは隣接帯しか接触しないため実害はないが、**凡例は全ペア文脈**であり、凡例側は色以外の識別（ラベル文字・並び順）に依存し続ける。P-5（8グループ集約）を不採用としたため、この制約は残る。

### R-2 【一部改善済み】教養娯楽と外食が凡例上で判別しづらい

採用トレードにより、教養娯楽（h5）と外食（当初 h15）が同一ティア・近接色相になった。外食を **h15 → h28** に調整した結果、この非隣接ペアの分離は改善したが、フロア（15）はまだ下回っている。

| ペア                    | light ΔE（通常視力・h15時） | light ΔE（通常視力・h28後） | dark ΔE（通常視力・h28後） |
| ----------------------- | --------------------------- | --------------------------- | -------------------------- |
| 教養娯楽 ↔ 外食         | 3.1                         | **7.1**                     | **7.8**                    |
| 家具・家事用品 ↔ 諸雑費 | 8.5                         | 8.5（変更なし）             | 7.4（変更なし）            |

いずれも積み上げ上では非隣接（間に他の帯が入る）ため隣接ゲートは通過する。h28 化により教養娯楽↔外食のΔEはほぼ倍増（3.1→7.1 light / 3.4→7.8 dark）したが、依然フロア15未満であり、**凡例では2チップ離れて並ぶだけで判別しづらい状態は残る**。

**改善案（未適用）**: 住居（h250）と教養娯楽（h5）の色相を入れ替える。検証すると light / dark とも `ok = true` を維持したまま、2つの近似赤が **スロット1と11＝積み上げと凡例の両端**に分離され、視線移動距離が最大化される。適用可否は要判断。

- 適用時: 住居 `#a0104b` / `#b31355`、教養娯楽 `#0c5a9a` / `#0f66ac`
- 副作用: 住居が赤系、教養娯楽が青系となり意味的な自然さは下がる

### R-3 明暗交互配置による「縞」の見え方

ティア交互が分離を担保する仕組みである以上、積み上げ全体は明暗が交互に並ぶ見た目になる。これは機能上の必然だが、印象面での評価は実装後のスクリーンショットで確認すること。V-3（ビジュアル回帰）を不採用としたため、**目視確認は手動で行う**。
