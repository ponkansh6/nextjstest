# 消費支出グラフのモバイル視認性改善プラン

作成日: 2026-09-11
状態: 採用項目を実装・検証済み
対象: 消費支出（名目・実質）
進め方: ユーザー指示に従い、サブエージェントを使用しない。

## 目的

スマートフォンで、推移・表示期間・費目・選択した四半期の値を読み取りやすくする。グラフまでの距離を短くし、文字を小さくせず描画領域を確保する。

## 現状と根拠

以下は採用項目の実装差分、ブラウザーE2E、および実DOMの寸法測定に基づく。実機での確認は今回の対象外であり、実施していない。

## 維持する表示契約

- Plan24と現行OpenSpecを優先する。2017Q4以前は民間最終消費支出の単独棒、2018Q1以降はCTI費目の積み上げ棒とする。
- 両系列の重複、独立した民間最終消費支出線、境界を埋める補間を追加しない。Plan05の旧2017Q1境界は採用しない。
- 名目・実質の費目と四半期フィルターの連動、データ値、正規化、出典、表・CSVの値を維持する。
- 合計は既存どおり表示対象の値で算出する。費目を絞った場合は「表示中の合計」と明示し、全費目合計との誤読を防ぐ。

## 改善案と優先順位

### P0: 描画領域・文字・凡例

1. 消費支出専用のモバイルスタイルを設ける。カード内の左右余白、Y軸幅、チャート右余白を実測して削減する。目安はY軸40〜48px、右余白8〜12pxとし、最大桁数のラベルが欠けない値を選ぶ。Y軸のゼロ起点を維持する。
2. X軸は利用可能幅とラベル幅から目盛り数を決め、開始・終了を優先する。四半期は `2025 Q1` または年とQの2段表記にする。1点・同一年・全期間も扱う。軸文字は最低12pxとする。
3. モバイルは名目・実質とも凡例を初期折りたたみにする。閉じた状態でも「費目・四半期を変更」と選択数・絞り込み状態を表示する。連動の説明は両側で認識できる位置に置く。
4. 展開後の費目名は14px以上、操作領域は44×44px以上を目標とする。折り返しを許容し、省略だけで費目名が読めなくなる状態を避ける。色に加えて選択状態とフォーカスを示す。凡例自体を44pxへ拡大する案は不採用とし、凡例は32px最小方針とする。

### P1: 密集した棒と詳細表示

1. 全期間の概要を維持し、消費支出の近くに「直近5年」「全期間」の期間操作を配置する。既存の期間状態・操作を再利用できるか確認し、名目・実質で同一期間になるようにする。他グラフとの既存の期間連動を不用意に変えない。
2. 拡大時の棒幅・間隔を調整する。年次集約や間引きで四半期データを消さず、全期間で細い場合は期間操作から詳細へ進める。グラフや凡例への新たな横スクロールは導入しない。
3. 選択中の四半期を背景帯などで明示する。色は既存の費目対応を維持し、ライト・ダーク両方で不透明度と境界表現を調整する。細い費目を太い境界線で隠さない。
4. 下部詳細は費目名を14px以上、合計を16px以上とし、数値を右揃えにする。期間ラベルの文字サイズは承認対象から除外する。初期は上位5件を維持し、「全N費目を表示」で残りを確認できるようにする。上位順であることを明示する。
5. 詳細パネルにsafe-areaを考慮し、展開内容は内部スクロールさせる。閉じる操作を常に到達可能にし、閉じた後の再タップ、ページスクロール、短い横向き画面を検証する。

共有tooltip・軸・CSSへの変更は消費支出向けオプションまたは専用クラスで適用し、他グラフへの影響を限定する。

## X軸ラベルの実座標検証に関する示唆

以下は未完了の監査原因(1)(2)に対する検討材料であり、追加実装や検証の実施結果ではない。

- **取得対象を先に確かめる。** Rechartsの既定tick用クラスがカスタムtickにも付くとは限らない。実際のX軸DOMを確認し、`XAxisEdgeTick` が描画したSVGの `text` を対象にする。`tspan` 単位では複数行を別ラベルと誤認するため、まず親の `text` 全体の矩形を扱うとよい。
- **0件取得を成功にしない。** チャートが表示領域に入り、LazyMount・ResponsiveContainer・フォントの反映が落ち着いた状態で取得する。描画対象データから期待するラベルと取得した文字列を照合し、件数不足・空文字・非有限座標・ゼロサイズを判定前に検出する。固定時間の待機より、要素の存在と矩形の安定を待つ方法を検討する。
- **座標系をそろえる。** `getBoundingClientRect()` はviewport基準のCSSピクセル、`getBBox()` とSVGの `viewBox` はSVG側の座標なので、そのまま比較しない。画面上の重なりが目的ならラベル・SVG・表示コンテナーをすべて `getBoundingClientRect()` で取得する方が単純。SVG座標で判定する必要があれば `getScreenCTM()` による変換を検討する。
- **はみ出しと重なりを分ける。** はみ出しはラベル矩形とSVGの可視領域を比較し、祖先のoverflowによるクリップも別途確認する。X軸ラベルはプロット領域の外に配置されるため、棒の描画領域に収まることを条件にしない。重なりはラベルを実際のX座標順に並べて矩形の交差を調べる。2段表記ではY方向の交差も考慮する。
- **誤差と見た目を切り分ける。** 小数ピクセルの丸めに対する小さな許容差と、読みやすさのためのラベル間隔は別の値として扱う。失敗時に文字列・矩形・比較対象領域・viewport・スクリーンショットを残すと、取得漏れと本当の衝突を切り分けやすい。
- **小さなケースから広げる。** まず390px幅・名目の1ケースで開始／終了を含む全ラベルが取れることを確認し、その後320 / 375 / 430px、実質、単一年・1四半期へ広げる。目盛り選定の単体テスト成功やE2E全体の成功だけでは、描画後の実座標を検証した根拠にはならない。

この追記では監査原因(1)(2)を、実DOMのラベル要素と表示矩形で検証する実装へ更新した。(b)の過去のE2E成功記録とは区別し、テスト実行結果は親エージェントの検証ゲートで確認する。

### 追記: 4幅で文字矩形を取得できない場合の具体的な切り分け

ユーザーから4幅で引き続き失敗しているとの報告を受け、現行E2Eとインストール済みRechartsのコードを確認した。以下はコードに基づくアドバイスであり、E2Eの再実行・修正は行っていない。過去の(b)の成功記録を、現行の実座標検証が成功している根拠にはしない。

**最初に直す候補は矩形APIではなく、ラベルを取得するセレクター。**

- `tests/e2e/consumption-mobile-readability.e2e.spec.ts` は `.recharts-xAxis .recharts-cartesian-axis-tick` を取得し、その子の `text` を探している。エラー `X tick native text geometry is unavailable` は、矩形APIを呼ぶ前の `if (!text)` で発生する。現段階では「ブラウザーが文字を測定できない」とは判断できない。
- ローカルの `node_modules/recharts/lib/cartesian/CartesianAxis.js` では、`.recharts-cartesian-axis-tick` は **目盛り線側のグループ** として生成され、ラベルは別の `.recharts-cartesian-axis-tick-label` に描画される。`tickLine={false}` の場合、目盛り線側は空のグループになり得る。その子を何度待っても文字は現れない。
- ラベル群には `.recharts-xAxis-tick-labels` が付く。まず対象チャート内の `.recharts-xAxis-tick-labels .recharts-cartesian-axis-tick-label text` を取得する案を検討する。ラベルは `ZIndexLayer` を経由するため、`.recharts-xAxis` の子孫であることも実DOMで確認するまでは前提にしない。クラス構造が変わる場合は、専用の識別属性をカスタムtickへ付ける案もある。
- 現行の `XAxisEdgeTick.tsx` はすでにネイティブの `<text>` を返している。測定のためにさらに描画コンポーネントを置き換えたり、文字数から推定幅を作ったりする前に、正しいラベル要素を選べているかを確認する。

**同時に見直す候補。**

1. `section.querySelector("svg")` はタイトルの情報アイコンなど、チャート以外のSVGを拾う可能性がある。対象チャートの `svg.recharts-surface` を特定し、ラベルの `ownerSVGElement` と一致することを確認する。別SVGとの比較では、文字取得を直してもはみ出し判定が誤る。
2. Y軸にも同じ旧tickセレクターを使っているため、数値ラベル取得を同様に確認する。空のグループの文字列を `Number("")` で変換すると0になり、数値tickが存在するように見えてしまう。空文字を明示的に除外し、期待するラベルの存在を検証する。
3. tick件数・ラベル文字列・矩形は、同じ実際の `text` 要素配列から取得する。線グループの件数をラベル数として代用しない。取得した矩形について有限値・正の幅と高さを確認してから、重なりやはみ出しを判定する。
4. まず390px幅の1ケースで、線グループ数・ラベル数・各ラベルの `outerHTML`・所有SVG・矩形を診断出力する。文字取得が成立した段階で残り3幅と名目・実質へ広げる。固定待機の追加や許容誤差の拡大では、今回の取得対象の不一致は解消しない。

正しい `text` を取得してなお矩形がゼロの場合に限り、表示状態・フォント・レイアウトの安定待ちを調べる。その後の代替案として `getBBox()` と `getScreenCTM()` による座標変換を検討できるが、要素未取得を別の測定APIで回避しようとしない。
