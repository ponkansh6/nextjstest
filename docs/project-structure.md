### Alias と実行境界

`tsconfig.json` の `@/*` は `src/*`、`@server/*` は `server/*` を指します。`shared/` は独立したトップレベル領域です。これは TypeScript の `paths` 設定であり、Vitest等の実行時aliasが自動で一致する保証ではありません。移動時は各実行環境の設定を別々に確認します。

現行のCTI表示はPlan40の四半期経路を `CpiChart` から描画します。旧Plan40年次表示用の `CtiAdjustedSeriesSection.tsx` は未使用だったため削除済みです。Plan39の年次measurement、loader、projection、data contractおよびそれらのテストは独立して維持します。

`src/app` 配下では `page`/`layout`/`route` 等のファイル規約がURL・実行境界を決めます。フォルダー整理でも公開URL、route handler、Server ComponentからClient Componentへのprops契約を維持します。`'use client'` を起点とする依存を確認し、`server/` の処理や秘密情報をclient bundleへ取り込まないでください。ディレクトリ名・aliasだけではserver-only境界は強制されません。

## Git状態と生成物の扱い

追跡状態と用途・再生成可能性は別の軸です。確認済みの例では、`docs/refactoring-plan.md`、列挙したscript資料、`.github/workflows/main.yml.bak` はGit追跡済みです。`data/source/` と `results/` にも追跡ファイルがありますが、ディレクトリ内の全ファイルが同じ状態とは限りません。`.next/`、`node_modules/`、`.vitest-attachments/`、`artifacts/`、`log/`、`.vercel/` はrepo `.gitignore` の対象です。`.tmp/` はrepo `.gitignore` ではなく、このcloneの `.git/info/exclude` によるローカル除外です。`.next/`、`node_modules/`、`.vitest-attachments/` 等の一般的なbuild/test出力はignore設定から生成物候補と分かりますが、個々の内容・再現性までは調査していません。`artifacts/`、`log/`、`.vercel/`、`.tmp/` のファイル単位の追跡状態・用途・再生成可能性も断定しません。ignoredであることだけでは削除許可の根拠になりません。その他の未追跡状態は対象ごとに確認し、秘密値をログや台帳へ複写しないでください。
