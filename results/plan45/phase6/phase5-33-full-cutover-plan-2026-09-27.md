**Date:** 2026-09-27  
**Status:** Complete; all 13 batches B01–B13 are accepted.
**Parent:** `shared_plan/45-vitest-browser-mode-e2e-migration-plan.md`

## Objective and current ledger

Fully move the 33 scenarios classified E-eligible by Phase 5 from Playwright E2E to permanent, failure-enforcing Browser Mode route tests. Preserve each original source action, context, and assertion boundary. Remove only the duplicate Playwright assertions after the matching Browser Mode batch passes and receives independent review.

Final accounting is `A=123`, `E=123`, `M=123`. The six former partial scenarios (#12, #30, #70–73) are already full cutovers. All 13 Phase 6 batches, B01–B13, are accepted as full cutovers; all 33 eligible scenarios are migrated and none remain Playwright-owned in this Phase 6 cohort. Their Phase 5 probes established feasibility only and did not increment M. No scenario was proven impossible under Browser Mode.

This follow-on plan expands Phase 5's feasibility-only scope at the user's explicit request. It does not reinterpret the historical Phase 5 plan or claim that diagnostic observations were already full migrations.

## Evidence and runtime constraints

- The 15 rendering/data and 18 interaction probes and their case-level results are listed in `results/plan45/phase5/phase5-feasibility-execution-results-2026-09-27.md` and `results/plan45/phase0/scenario-inventory.md`.
- Current validation baseline: production Browser Mode suite: Chromium 80/80 and WebKit 21 passed / 5 skipped; full Playwright E2E: 31 passed / 18 skipped; real-consumption file: 7/7 passed. Raw focused logs for the historical six partial cutovers were not retained.
- Browser Mode production route tests use the repository's Playwright provider through `tests/browser-mode/*-route.command.ts` and `scripts/run-next-route-poc.mjs`; they run against a fresh production build. CI must invoke the permanent 33-case suite after build.
- Standard Next Vitest unit guidance does not cover async Server Components; this migration uses the repository's existing Browser Mode production-route pattern, not component-only rendering as a substitute.
- Keep source-required `__MOUNT_ALL__`, browser project, color scheme, viewport, mobile touch, network-idle, URL, CSV/download, and data-readiness setup exactly where the source fixture uses them. Do not infer new behavior from the diagnostic probe harness.

## Permanent test requirements

For every stable ID:

1. Map the source Playwright test's full action sequence and every assertion to a named Browser Mode assertion. The test must fail if the source predicate fails; logging `outcome` or `contractMatch` without asserting it does not qualify.
2. Preserve the source test's browser, route, fixture, viewport, scheme, data interval, and interaction semantics. Reuse the real production route and public UI contract.
3. Keep downloads as downloads and parse/compare all source-required rows, columns, metadata, and values. A sampled January 2025 row is not a substitute for whole-period parity.
4. Run the focused batch, have an independent reviewer check its source-to-destination crosswalk, then remove only the assertion slices covered by that batch from Playwright. Leave all non-covered assertions in E2E.
5. Update the row-level inventory, residual Playwright ownership, M count, validation logs, and checkpoint artifacts before starting the next batch.
